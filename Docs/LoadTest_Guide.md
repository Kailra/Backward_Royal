# 부하 테스트 가이드 (Backward Royal)

실제 서비스와 유사한 부하를 주어 **다인원 접속**과 **병목 구간**을 확인하는 방법입니다.

---

## 1. 다인원 접속 테스트 (누가 몇 명 접속하는지)

### 1-1. 에디터 PIE (Play In Editor)로 2~4명

- 에디터에서 **Play** 옆 **▼** → **Advanced Settings** (또는 **Number of Players**).
- **Number of Players**를 2, 4 등으로 설정 후 실행.
- 한 프로세스에서 여러 창이 뜨며, **1번 = Listen Server(호스트)**, 나머지 = 클라이언트.
- **제한**: 같은 머신 한 대에서만 동작하며, 4~8명 이상은 무거워질 수 있음.

**확인할 것**:  
- 2명, 4명, 8명일 때 각각 방 생성 → 방 찾기 → 참가 → 게임 시작까지 끊김/크래시 없이 되는지.

### 1-2. 패키징 후 여러 클라이언트로 접속

1. **서버(호스트) 1대**
   - 패키징된 게임 실행 → **방 만들기** → 대기.
   - 또는 전용 서버로 실행한다면:  
     `YourGame.exe <맵경로>?listen -log` (예: `BackwardRoyal.exe /Game/Main/Level/Main_Scene.Main_Scene?listen -log`).
2. **클라이언트 여러 대**
   - 같은 PC에서 **패키징 exe를 여러 번 실행**해 각각 방 찾기 → 참가.
   - 또는 다른 PC/노트북에서 같은 LAN에 붙여 동일하게 방 찾기 → 참가.
3. **인원을 늘려가며**  
   - 2명 → 4명 → 6명 → 8명(최대 인원)까지 반복.

**목표**:  
- 최대 인원(8명)까지 동시 접속 시 로비/게임 진행이 안정적인지, 끊김·이상 동작이 없는지 확인.

---

## 2. 병목 구간 확인 (서버가 느려지는 지점)

### 2-1. 콘솔 명령 (실행 중인 게임에서)

- **`~`(틸드)** 로 콘솔 열기.
- **호스트/서버**에서 아래 입력.

| 명령 | 설명 |
|------|------|
| **StatServer** | [부하 테스트용] 현재 플레이어 수/맵 요약 + stat 안내 (프로젝트에서 추가한 명령). |
| **stat unit** | 프레임 시간(게임/렌더 스레드) 표시. 수치가 크면 병목. |
| **stat net** | 네트워크 패킷/대역폭 요약. |
| **stat game** | 게임 스레드 비용 요약. |

**해석**  
- **stat unit**에서 **Frame** 또는 **Game** 수치가 인원이 늘어날수록 크게 증가하면 → **게임 로직/틱이 병목**.
- **stat net**에서 **OutPackets**/대역폭이 인원에 비해 과하게 크면 → **복제량·RPC 과다** 의심.

### 2-2. StatServer 사용 순서 (권장)

1. 호스트로 방 만들고, 클라이언트 2명 접속.
2. 콘솔에서 **StatServer** 입력 → 플레이어 수/맵 확인.
3. **stat unit** 켜 둔 채로 인원을 4명 → 6명 → 8명으로 늘리며 **Frame/Game 수치 변화** 확인.
4. 게임 시작 후 스테이지에서도 동일하게 **StatServer** + **stat unit**으로 확인.

이렇게 하면 **“몇 명부터 수치가 나빠지는지”**를 빠르게 볼 수 있습니다.

### 2-3. 프로파일러 (자세한 병목 분석)

- **Unreal Editor**에서 **Window → Developer Tools → Session Frontend** (또는 **Profiler**).
- 패키징 빌드에서는 **Unreal Insights**로 프로파일링 세션 수집 후 분석.
- **게임 스레드**에서 시간을 많이 쓰는 함수(Update, Tick, Replication 등)를 확인해 병목 구간을 좁힙니다.

---

## 3. 강제 종료·예외 동작 확인 (Alt+F4 등)

- **호스트**가 Alt+F4로 종료 → 나머지 클라이언트는 메인 메뉴 등으로 정상 이탈하는지.
- **클라이언트**가 Alt+F4로 종료 → 호스트/다른 클라이언트의 로비 인원·목록이 바로 갱신되는지.
- **일부만 끊고** 다시 방 찾기로 접속해 보며, 세션 정리·데이터 보존이 기대대로인지 확인.

---

## 4. 정리 체크리스트

| 항목 | 방법 |
|------|------|
| 다인원 접속 | PIE 2~4명 + 패키징 후 2/4/6/8명 접속 |
| 병목 확인 | 콘솔: **StatServer** → **stat unit** / **stat net** |
| 상세 분석 | Session Frontend / Unreal Insights |
| 예외 동작 | 호스트/클라이언트 Alt+F4 후 인원·세션·재접속 확인 |

**StatServer**는 서버(호스트) 콘솔에서만 유효합니다. 클라이언트에서 입력하면 "서버에서만 사용하세요" 안내가 나옵니다.
